# AGENTS.md

## Project state

Express 5 API (CommonJS, Node 24) that talks to Postgres through Sequelize 6 (`pg`), never raw `pg` queries. `README.md` is the user-facing guide for consuming the API — keep it updated; trust `package.json`, `src/app.js`, and `.opencode/agents/`.

## Commands

- `npm start` runs the API (`node src/index.js`); `npm run dev` uses `node --watch`.
- `npm test` runs the unit suite; single module: `npm test -- <nombre_modulo>` (e.g. `npm test -- health`). `npm run test:coverage` for coverage. Unit tests never need Postgres.
- `npm run test:integration` runs `jest.integration.config.js` against a real Postgres database whose name must end in `_test` (default `bread_king_test`, override with `DB_NAME_TEST`); it creates the DB, applies the migrations and runs the seeders automatically. Requires `docker-compose up -d db`. `npm run test:all` runs unit + integration.
- `npm run db:create`, `npm run db:migrate`, `npm run db:rollback` and `npm run db:seed` use `sequelize-cli` through `.sequelizerc` (CLI config in `src/config/sequelize-cli.js`, migrations in `migrations/`).
- Seeders live in `seeders/` and run with `npm run db:seed` (idempotent; they populate the `roles` table).
- Prettier is installed: `npx prettier --write <archivo>` or `npm run format`. No lint or typecheck tooling exists.
- `docker-compose up` builds `api` + `postgres:17-alpine` (`db`). Only standalone `docker-compose` v1 is installed on this machine; the `docker compose` plugin is not.
- Env vars: `PORT`, `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_NAME_TEST`, `DB_HOST_TEST`, `DB_USER`, `DB_PASSWORD`, `JWT_SECRET`, `JWT_EXPIRES_IN` (see `.env.example`); the API defaults to port `3001` when `PORT` is unset, Sequelize defaults to `bread_king` on `localhost:5432`, and integration tests connect to `localhost` unless `DB_HOST_TEST` is set.

## Structure

- All source lives under `src/`: `src/index.js` boots the server, `src/app.js` builds the Express app (tested with supertest).
- One folder per module: `src/<modulo>/index.js` (Express router) + `src/<modulo>/<modulo>.test.js`. Existing: `hello` (`GET /hello-world`), `health` (`GET /health`, returns 503 when the DB is unreachable), `auth` (`POST /auth/login`, `GET /auth/me`, `GET /auth/setup-status`, `POST /auth/register-admin`; helpers in `src/auth/`) and `users` (`POST /users`, admin-only).
- Sequelize models live in `src/models/` (`user`, `role`); `src/database/index.js` exports the shared Sequelize instance.
- Swagger UI is served at `/docs`, generated by `src/config/swagger.js` from the `@openapi` JSDoc blocks in the routers.
- Manual requests live in `http/*.http` and use the `{{baseUrl}}` variable defined in `http/http-client.env.json` (port `3001`). IntelliJ/VS Code HTTP Client only resolves `{{baseUrl}}` when an environment is explicitly selected; otherwise it sends the literal `{{baseUrl}}` and the request fails. The file defines the same `baseUrl` in both `default` and `dev` so clients work without extra config; Kulala (nvim) reads `$kulalaShared` (duplicated from JetBrains' `$shared`) and defaults to the `default` environment, or run `:Kulala env dev` to switch.

## Workflow conventions (enforced by `.opencode/agents/`)

- TDD: failing Jest test `<modulo>.test.js` first, then implementation in `<modulo>/index.js`.
- Coverage target >90%; mutation score target >80% (delegate to `@mutation`), then `@refactor` for design patterns.
- One branch per task: `feature/<name>` or `fix/<name>`. Tasks live as GitHub issues (source of truth: `gh issue list`); do not create or move files under `issues/`. Use `gh issue view <n>` to read one, `gh issue edit <n> --add-label en-progreso` when starting and `gh issue close <n>` when done.
- GitHub issues follow the fixed HU template: `# HU-NN — <title>`, then `## Historia de usuario`, `## Alcance`, `## Requerimientos funcionales` (`### RF-NN`), `## Requerimientos no funcionales` (`**RNF-NN**`), `## Contrato de la API`, `## Criterios de aceptación` (checkboxes), `## Fuera de alcance` and `## Dependencias técnicas` (new/modified files and env vars). Keep the same headings and numbering when writing a new one. Useful labels: `historia-de-usuario`, `en-progreso`, `completado`.

## Rules

- Every endpoint/example must be documented in Swagger: add or update the `@openapi` JSDoc block in the module router so users can consume it at `/docs`.
- Every new or changed endpoint must also be documented in `README.md`: explain how to use the API (method, path, auth, request/response examples) so a user can consume it without reading the code.
- Always run `npm test` after any change to prove the new feature doesn't break existing behavior.
- Format every changed `*.js` file with Prettier (`npx prettier --write <archivo>`) before finishing.
- No file may exceed 300 lines; split it into smaller modules when it approaches that limit.

## Gotchas

- `docker-compose` v1 + Docker 28 fails when recreating existing containers (`KeyError: 'ContainerConfig'`); run `docker-compose down` before `up -d` after a rebuild.
- The legacy GitLab remote is kept locally as `gitlab`; `origin` points to GitHub. Never commit credentials or tokens.
- GitHub CLI (`gh`) is available and authenticated for this project.
